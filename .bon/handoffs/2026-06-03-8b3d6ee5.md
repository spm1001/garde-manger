## For Claudes to come

**A count in a brief that gates an irreversible action is a hypothesis — and "key-namespace mismatch" is a classic way the count lies.** When System A keys an entity as `X` and System B stores it as `prefix-X`, a naïve set-membership check (`X in B`) silently misclassifies the *entire* prefixed population. Here garde's DB keyed subagent sessions `claude_code:{uuid}` while their on-disk files are `agent-{uuid}.jsonl`, so `uuid in disk` flagged **all ~1,702 subagents as "off-disk"** — manufacturing a "1,645-source / 106-substantial ark" that justified the whole decommission's DB-deletion caution. The real off-both-disks set was **3 trivial sessions**. The tell: an off-by count that suspiciously matches a known subpopulation's size (1,645 ≈ 1,702 subagents). The corrective is cheap and load-bearing: before building on (or deleting because of) a count, re-derive it from the substrate, handle both key namespaces, and ground-truth one element (here: a Nov-26 session the count called "off-disk" had its JSONL right there on disk, mtime ≠ created-date being the second confound). Composes with verification-by-substrate and *count-before-adjective*; the specific new shard is **the prefix/namespace mismatch as a measurement bug**, distinct from a stale or fabricated number.
